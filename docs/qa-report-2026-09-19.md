## Confirmed blocker: database schema mismatch

The live `users` table lacks `name` and `role`. Both are mapped by `backend/app/models/user.py` and used by authentication queries.

Read-only reproduction:

```python
await db.execute(select(User.name, User.role).limit(0))
```

Result:

```text
ProgrammingError
asyncpg.exceptions.UndefinedColumnError: column users.name does not exist
```

The repository includes migrations `007_users_name.sql` and `008_users_role.sql`, but the current database does not contain their required user columns. This explains why an otherwise healthy database connection does not make registration or login work.

Browser reproduction: open `/login`, select **New here? Create an account**, enter a valid username/email/password, then select **Create account**. The backend returns HTTP 500; the browser reports `net::ERR_FAILED` and the form displays `Network Error`. The failed response lacks an `Access-Control-Allow-Origin` header, while the OPTIONS preflight succeeds.

Next step: review/apply the existing migrations to the intended local database, then repeat registration, login, and the full document journey. The migration runner is `backend/scripts/run_migration.py`. It was not executed during this testing-only pass.

## Additional source-review findings — not runtime-verified in this pass

These findings from the code remain relevant after resolving the schema blocker:

1. **Critical:** `/auth/reset-password` accepts email plus a new password without a reset token or other proof of ownership (`backend/app/modules/auth/service.py`).
2. **High:** `/users` and `/users/{user_id}` have no authentication dependency (`backend/app/modules/users/router.py`). The current schema failure prevents verification of their normal data response.
3. **High:** An existing admin token bypasses a fresh database role/active-status check (`backend/app/modules/auth/deps.py`).
4. **High:** Query keys are not user-scoped for documents/actions, and logout does not clear the query cache. Account-switch leakage needs browser verification after login works.
5. Assistant replies are scripted, settings edits are not persisted, and reminder delivery is not implemented. These features cannot be signed off as fully functional.
